# Changelog

## Workspace 0.1.0-alpha.6 — Research management and wide conversations

Move management pages to the left and render the native research conversation in the central area. Preserve the current conversation draft across management navigation and temporary file or artifact inspection. Collapse technical records by default, show readable data and artifact summaries, and provide explicit experiment-context copying. Use native modal focus and dismissal behavior for utility panels and compact navigation.

## Workspace 0.1.0-alpha.3 — Companion research UI

Add the native hydrology sidebar entry and research page as an independent package. Read real Study activities and artifact dependencies, preview hash-checked artifacts, and embed native DSH conversations. Recover conversation evidence through Session Projection. File access is scoped to registered research; the terminal panel currently exposes saved execution records.

## 0.1.0-alpha.8 — Guided hydrology conversations

Introduce the four capability areas with ready-to-send examples for new users. Collect missing inputs gradually, explain progress and results in everyday language, and give relevant next actions. Capability introductions do not trigger scientific work; explicit tasks retain environment checks and failure stops.

## 0.1.0-alpha.7 — Preserve failure stops across automatic follow-ups

Keep failed hydrology requests blocked when background notifications advance the framework turn. Only a new user instruction restores admission. The real DSH pipeline regression covers automatic follow-ups and explicit user steering.

## 0.1.0-alpha.6 — Scientific result inspection and failure admission

Block new hydrology work after a tool or background job fails in the same user turn; retain diagnostics and output collection, isolate agents, and reset on a new user turn. Return task-based status queries and saved effective algorithm parameters. Add hash-checked JSON artifact inspection within the selected Study. The desktop CPU LSTM test completed two epochs, 14 optimizer steps and fixed-checkpoint evaluation over 15 days without additional optimization.

## 0.1.0-alpha.5 — Agent onboarding corrections

Declare Study consent as an explicit JSON boolean while retaining strict rejection of strings and numeric substitutes. New SelfMade CSV projects disable native cache preparation; selected-value preflight can proceed directly to explicit Study initialization. The hydrology preset and shared guidance explain when caches are required and stop repeated parameter experiments after a failed correction. Existing projects, source data and staged failure evidence remain intact.

## 0.1.0-alpha.4 — Windows acceptance fixes

Use the same quick calibration defaults in preflight and execution; verify precise and custom settings without model evaluations. Shorten generated project directories to leave room for Windows artifact filenames. Reject Study mutations during owned jobs or project preparation, and prevent cancelled preparation from changing the conversation binding. The desktop hydrology expert completed a real metrics tool call and read its native job output.

## 0.1.0-alpha.3 — Windows capability candidate

Add local-data onboarding with immutable per-project declarations, supported-interface discovery with execution-time deployment checks, source metadata for research reuse, and quick/precise/custom calibration modes. New project policies disable cumulative and per-task application quotas and scientific wall-clock stops while retaining actual accounting, algorithm stops and explicit finite-limit support. Both standard and hydrology-expert modes completed real XAJ calibration/validation, CPU LSTM training/checkpoint evaluation and plotting in the target Next runtime. Dedicated workspace UI remains a later phase; Mac scientific acceptance follows Windows.

## 0.1.0-alpha.2 — local candidate

Add explicit host-configured research locations and durable conversation bindings. Ordinary and hydrology-expert sessions can select the same Study without copying scientific records. Reject unknown project IDs, switching during owned jobs, and stale selections after a configured location changes. Full data onboarding and the four-domain scientific workflow remain pending.

## 0.1.0-alpha.1 — local candidate

First publishable DSH bundle layout with a hydrology expert preset, globally available native tools, a pinned common-core payload and independent managed environment. Scientific workers use the shared Python execution library, DSH-owned jobs and cooperative cancellation. Installation and one real metrics operation have been checked on Windows; full four-domain workflows and macOS scientific acceptance remain pending. This candidate is not published to npm.
