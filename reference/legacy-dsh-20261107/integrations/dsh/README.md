# Hydrosystem 的 DSH 接入

本目录在 hydrosystem 同一仓库交付 DSH bundle，复用公共工具目录、参数校验与执行实现。MCP 和 CLI 继续独立使用，科学算法仍由上游包提供。

当前开发包面向 Windows x64 的 DSH V0.2.1-rc.5。托管模式在桌面 profile 下自动准备独立 Python 和发布锁依赖，使用合成数据开放四模块演示授权；工作类操作通过 DSH 内置 jobs 执行。另保留只读源码原型，用于检查版本兼容与工具发现。

## 托管模式

用 `scripts/build_dsh_bundle.py --output <新的目录> --uv <固定 uv 可执行文件> --uv-licenses <同发行版许可证目录>` 构建。构建器复用原生安装器的 payload、wheel、导出锁和哈希，不维护第二套科学依赖。进入输出目录运行 `npm pack`，再用 `scripts/check_dsh_bundle.py <tarball>` 校验打包后全部 payload 文件，最后通过目标桌面自身的插件入口安装。

首次激活会下载依赖并创建 `<profile>/hydrosystem/releases/<release-id>/hydrosystem/.venv`；源码快照、节点配置、缓存、数据和研究分别保留，不修改系统 Python 或主目录的数据配置。首次准备可能延迟桌面启动；安装日志位于对应 release 的 `.hydrosystem/installation.log`，结果为 `setup-result.json`。失败保留报告，不替换现有研究，也不通过新建根目录绕过安装锁。

科学调用返回 `job_id` 后，Agent 使用内置 `job_output` 获取结果，使用 `job_kill` 请求取消；科学任务、实际用量与产物仍由公共运行时记录。取消须等待登记的工作进程退出，未能确认清理时报告 `EXECUTION_CLEANUP_PENDING` 并保留容量。完全退出桌面后不保证计算继续。

当前演示配置提供 28 项公共科学工具，另有 1 项 DSH 工作台读取工具；下载和缓存准备没有授权。数据为随发行包的两流域合成样例，安装不会创建 Study 或执行科学任务。示例科学权限仍有有限单次率定、训练及总时限；快速/精细方案和可选限制改造尚未交付，不能将此开发包视作第一阶段最终版本。

## 水文研究 demo

安装本 bundle 后，侧边栏提供“水文工作台”，新会话可选择“水文研究员”。工作台读取当前绑定节点的 Study，展示最近 100 条活动、XAJ 率定与验证指标和最多 6 张经哈希核验的 PNG；刷新只读取记录，不开始计算。“研究实例”发现当前节点 studies 目录中的最多 200 个直接子目录，支持选择已有研究和明确输入目标后新建研究。选择保存在当前查询会话；管理页同时选择已有 DSH 工作区，新建对话时一次绑定工作区、水文 preset 和该研究，已有对话保留自己的绑定。科学任务运行期间拒绝切换其所属会话的研究，提交后的后台任务固定原研究根。跨节点研究发现另行实现。

对话标题栏提供“文件、产物、实验、终端”四个快捷入口，均在 DSH 原有右侧栏打开；文件树、文件预览与终端复用 DSH，产物和实验由水文工作台注册。中间保持对话，实验页展示节点当前运行的科学任务及所选 Study 的活动、任务引用和结果。科学报告提供指标、时段、停止原因、用量及原始证据，图表可点击展开。使用框架自带的放大、关闭、分栏和布局恢复。全页工作台仍保留为辅助概览入口。新建空白会话需要先按 DSH 的原有流程选择工作区并开始对话，再使用标题栏入口；现有研究对话可以直接打开右侧成果区。

右侧标签可见时，当前会话的后台任务登记、结束和轮次结束事件触发读取刷新，不执行科学计算；检测到节点科学任务运行时，可见页每 5 秒读取状态，隐藏或卸载停止检查。手动刷新继续可用。首次读取时没有运行任务且新任务来自另一会话，需要手动刷新。图表与报告详情及分类按会话保存在本机浏览器存储；对话中的任意文字引用尚不能自动定位到自定义成果标签。

工作台通过内置会话命令 `/hydro_workspace` 读取与 Agent 工具 `hydrosystem_workbench` 相同的结果；命令使用独立会话传输，Agent 工具只返回图表引用，不返回图像正文。UI 的只读投影暂直接读取 Study 0.2 的活动文件；正式版应统一提供公共研究证据查询接口。损坏或越界的证据显示警告，保留其他可读结果。图表点击下载 PNG，任务行可展开查看参数、结果与引用。

此 demo 不改变已安装的科学 Policy，也不表示第一阶段的剩余功能已经完成。preset 明确要求后台句柄通过 `job_output` 获取最终结果，区分执行成功、预测效果与算法收敛。MCP、CLI 仍使用原有公共业务实现。

## 插件组成与环境

一个 bundle 装配节点运行时（根入口）、水文工具（`/tools`）、研究管理（`/research`）、环境查询（`/environment`）四个 Host 插件，以及客户端工作台和官方 preset。运行时服务负责固定环境与进程生命周期；工具只编排公共科学接口；研究插件提供 `/hydro_studies`、`/hydro_workspace` 与只读 Agent 工作台工具；环境插件提供 `/hydro_environment`。关闭研究或环境插件会显示命令不可用，不将查询错误解释成空研究。更改 Host 组合后须正常退出并重开 Desktop，使前后端加载同一版本。

“环境与节点”读取绑定解释器的公共环境状态，显示 Python、虚拟环境、五个上游包实际与要求版本、来源、锁指纹、私有 uv 版本、CPU/内存和执行域。本页只查询元数据，不安装依赖、不执行科学验证、不切换环境；其他已部署节点和环境切换尚未接入。解释器或元数据失败保留错误，由用户刷新重试。账号和模型接入留待独立插件，本 bundle 不注册 Codex 授权入口。

## 原型准备

在已有锁定 `.venv` 的源码节点，用 Node 执行 `node integrations/dsh/build-prototype.mjs <新的绝对输出目录>`，再在输出目录执行 `npm pack`。构建器只复制 bundle 并记录显式源码绑定，不安装依赖、不创建 Study、不改变现有数据设置。输出目录的父目录须已存在；重复目标拒绝覆盖。

生成的 `connection.json` 属于本机原型工件，不提交到仓库。将打包工件交给目标桌面实例自身的插件管理入口；目录导入或打包成功都不等于桌面已激活，需分别记录安装、加载和普通 Agent 的实际调用。

## 正式交付待完成

跨节点 Study 授权历史发现、快速/精细率定方案、可选限额和时限，以及全量科学与异常恢复验收仍在开发。只读原型使用开发源码和现有环境；托管模式需要独立验证真实桌面加载、科学执行和取消，不能用环境安装通过替代。

公共工具定义位于 `hydrosystem/tool_definitions/`，`ToolCatalog` 负责部署过滤、独立 schema 和请求校验；MCP 使用同一目录。`python -m hydrosystem.bridge --help` 说明本地进程桥接入口，其部署路径由调用适配器绑定，模型请求只接受发现或具名工具调用。
