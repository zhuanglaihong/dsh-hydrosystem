### 第一阶段已确认的产品决策

以下 12 项来自本轮 grill-me 访谈，均已确认；表中是目标行为，不表示现有代码已经支持。

| 编号 | 主题 | 已确认行为 |
|---|---|---|
| D1 | 能力范围 | 普通 DSH Agent 使用全部当前公开研究能力；以 full 模式现有 30 项为覆盖基线。环境、部署与授权管理由插件或部署方完成，不全部变成 Agent 工具 |
| D2 | 环境归属 | 统一安装插件管理的私有 Python 环境与锁定依赖；DSH 管插件生命周期，插件复用 hydrosystem 环境实现，不修改系统 Python |
| D3 | 初始数据 | 随插件准备现有合成演示数据，不自动创建 Study、不自动执行研究任务；真实数据随后显式配置 |
| D4 | 后台任务 | 长操作接入 DSH 内置 jobs，提交后可以继续聊天；hydrosystem 保留科学任务和用量记录，不新增调度器 |
| D5 | 运行生命周期 | 首版保证 DSH 运行期间执行；完全退出应用后不承诺继续计算。重开后核查既有结果、中断记录和实际用量 |
| D6 | Study 绑定 | 每个会话首次明确选择已有或新 Study，之后保持绑定；识别到同一研究或历史相似工作时，先告知已有证据和本次打算，不静默合并研究 |
| D7 | 历史发现 | 在插件已登记且获授权的 Study 中跨会话、跨工作区查询；不扫描整盘，不因“相似”扩大权限 |
| D8 | 资源准入 | 沿用共享运行容量；占用时报告当前容量和执行，不自动排队。Agent 查询状态后再决定提交 |
| D9 | 科学账户 | 默认不以 Study 累计额度停止率定，也不施加独立的通用单次求值额度；持续记录实际模型求值。快速方案或显式配置的上限仍生效，保留未来有限额度能力 |
| D10 | 率定时限 | 默认不设率定总时长上限；保留显式设置时限的能力。连接、查询和数据访问等各自超时不等于率定总时限 |
| D11 | 率定方案 | 快速方案设置明确求值上限；精细方案默认无求值次数及总时长上限，按已验证算法停止条件运行。支持合法参数覆盖，完整记录有效设置和来源 |
| D12 | 默认率定 | 用户未指定方案时先快速率定；报告真实指标、求值次数和停止原因，并提供进一步精细率定或自定义参数的选项 |

快速方案是用户明确接受的有限求值例外，与默认不限累计额度并存。达到求值上限时保存合法的当前最好结果，报告“达到求值上限”，不能标记为已收敛；若未得到合法结果则报告失败。精细率定表示更充分的搜索或更严格的停止条件，其效果由独立验证指标评价。后续精细任务默认是新的不可变 Task，不宣称接续快速任务的优化器内部状态。

## 3. 同仓库架构与职责

```text
hydrosystem 仓库
├─ 公共执行层：操作、schema、Policy、Study、Task、Trial、Artifact、科学账户
├─ 上游适配层：四模块连接五个基础包，不复制科学算法
├─ MCP / CLI：保留既有入口和共享语义
├─ skills：保留一份能力指导，按需提供给各调用方
└─ integrations/dsh/（拟新增）
   ├─ 插件发行、环境接入、就绪与兼容检查
   ├─ DSH 工具接入和 Session 与 Study 的关联
   ├─ 水文 preset（第二阶段）
   └─ Client 界面扩展（第三阶段）
```

Python 包与 npm bundle 可以是两个发行工件，但属于同一产品和仓库，不建立第二套水文业务接口。具体 npm 包名在发布前核对可用性；目录结构在安装验证原型后固定。每个已发布 DSH bundle 明确对应的 hydrosystem 版本、发行工件哈希、锁指纹和支持的 DSH 版本范围，不通过运行时模糊匹配选择版本。

| 对象 | 唯一职责归属 | DSH 侧处理 |
|---|---|---|
| 科学操作、校验、预算、实际用量 | hydrosystem 公共执行层 | 传递结构化请求，保留结果和错误字段，不另算额度 |
| 模型、reader、训练、优化与指标算法 | 上游包，经既有 adapter 使用 | 只暴露经过适配和验证的能力 |
| 研究身份、任务与产物 | hydrosystem Study / Task / Trial / Artifact | 保存关联引用并查询，不以聊天记录重建科学账本 |
| 对话、推理、工具权限与 Agent 生命周期 | DSH | 通过插件与 preset 配置，不复制 Agent 循环 |
| 任务状态与结果展示 | hydrosystem 提供事实，DSH 提供视图 | UI 与 Agent 调同一操作；丢弃缓存后能重新查询 |

### 接入方式的决策

第一阶段先用一个已存在的只读操作做安装验证原型，同时验证一个长操作接入 DSH jobs。优先复用既有工具发现、schema、skill、错误与执行入口，用户不手写 MCP 配置。正式接入方式由 V0.2.1-rc.5 的实际插件 API 和后台原型共同确定。

已按桌面版对应提交 b830ec950faba0a46dda564be3e2d854afed94f1 检查：base bundle 包含 jobs-local/tool-jobs，但 MCP client 不会自动把普通同步工具调用转换为 DSH job；hydrosystem 当前 MCP 入口也是同步执行。因此“安装 MCP 后自然获得后台执行”不能作为实现假设。插件必须补齐任务生产者接入、状态通知和生命周期处理，使用 DSH 现有 jobs 注册与控制能力。

原型比较“既有 MCP 加 jobs 接入”与“DSH 原生工具桥接公共执行层”的实际可行性，只保留一条正式 DSH 调用路径。若需要原生桥接，先提取调用方无关的公共发现接口，不复制 MCP 工具表、部署筛选或科学规则。MCP、CLI 作为其他调用方的入口继续保留。长任务取消必须连到真实科学执行并等待清理；仅结束前端等待不能报告计算已取消。

当前 operations.execute 是共享执行入口，但完整工具发现和部署筛选还分布于 mcp/server.py。不能直接调用 execute 后另写一个手工工具清单，也不能绕过现有启动来源校验、摘要披露或部署授权。第三阶段读取研究视图所需接口应由 hydrosystem 提供公共查询，避免 DSH 直接依赖账本文件布局。

## 4. 第一阶段：让已安装桌面版使用 hydrosystem

### 4.1 全量能力范围与代表闭环

第一阶段覆盖当前已适配的公开研究接口，不仅交付四条演示。现有 full 模式覆盖基线如下；逐项名称及 MCP/CLI 对照以 [工具目录](../../docs/package-mcps.md) 为准，授权过滤以 [MCP 配置矩阵](../../docs/reference/mcp.md) 为准。实施新增的公共查询也须加入覆盖清单，不为保持“30”而遗漏验收。

| 能力组 | 当前工具数 | 必须覆盖的功能 |
|---|---:|---|
| 公共 | 4 | capabilities、同源指导、Study 初始化/查询/预算申请、runtime 状态 |
| hydrodata | 8 | 数据集目录/说明、流域、属性、时序、预检、纳管、获授权下载、缓存准备 |
| hydromodel | 7 | 模型目录/说明、预检、模拟、率定、任务状态、率定状态 |
| torchhydro | 6 | 模型目录/说明、预检、训练、评估、任务状态 |
| hydroutils | 5 | 能力发现、指标计算、过程线、降雨径流图、实测/模拟散点图 |

正常演示配置当前为 28 项；下载和缓存准备需单独显式授权，完整配置才是 30 项。安装不自动授予网络下载、任意数据或目录访问权；缺少权限时按配置隐藏工具或返回结构化拒绝。无配置、部分配置及 summary 模式继续遵守既有筛选规则。

| 能力 | 普通 Agent 的真实桌面代表链路 | 暂不自动扩张的范围 |
|---|---|---|
| 数据处理 hydrodata | 发现或纳管演示资产，读取属性和时序，检查具体选择 | 任意 CSV 转换、高级清洗和空间处理需单独定范围；现有能力不等于全套数据处理 |
| 模型率定 hydromodel | 查询模型与约束，预检，率定，引用实际 Trial 独立验证 | 不新增优化器、final selection 或 checkpoint/resume |
| 深度学习 torchhydro | 预检，已验证 CPU 模型训练，保存权重，用真实 checkpoint_ref 评估 | 不宣称任意目录模型可训练；GPU、分布式、续训和自动调参另议 |
| 绘图与评估 hydroutils | 读取真实序列引用，计算一个已有指标，生成一个已有基础图 | 不把已有模拟指标重复计算当成必经步骤；高级图后定 |

同一演示 Study 串起数据、率定验证、训练评估和绘图；缺少配置的模块明确报告未就绪，不返回空成功。随仓 SelfMade 合成样例是首版必过基线；真实数据作为随后显式选择的扩展验收，不阻塞合成基线开发。下载与缓存的现有功能仍需单独完成获授权的真实执行验收。合成数据用于验证接口、计算和记账，不证明科学拟合质量。

### 4.2 共享执行层需要调整的行为

| 现有实现或缺口 | 本阶段改动 | 验证重点 |
|---|---|---|
| 率定授权依赖有限 per-task 字段，Profile 默认推荐 64 次，只有累计额度可为 null | 将率定启用、用量计数和可选停止上限分开；默认累计不限额，精细模式单次也不限额，有限部署仍可配置 | 省略上限不会恢复为 64；不限额仍计数；显式有限额度继续生效，失败和中断实际用量正常结算 |
| timeout_seconds、科学子进程等待和外层 runtime 都可能停止率定 | 率定总时限默认关闭，显式设置时各执行层一致；控制请求和连接继续有各自超时 | 长任务跨过旧超时仍执行；显式时限停止、状态与清理一致；连接超时后先查状态 |
| 只支持显式算法字段和有限 model_evaluations，没有快速/精细方案 | 在公共解析步骤增加版本化方案与合法覆盖；默认快速；完整写入 Resolved Task 并同步发现信息、MCP、CLI、skill | 省略方案、两种方案、显式覆盖和非法字段；算法初始化所需求值量、随机种子、父 Trial 继承与停止原因均可追溯 |
| 上游 SCE-UA 当前调用要求 rep，通常是最大求值次数 | 先核实发布锁对应的 hydromodel/优化器是否支持无次数上限；必要时在上游增加明确支持并升级验证后的锁定基线，本仓仍用薄 adapter | 不用极大整数冒充无限；不复制 SCE-UA；上游未支持前精细不限次不能标为完成 |
| Study 当前以根目录访问，缺少跨会话授权发现 | 增加调用方无关的 Study 发现/摘要能力及授权登记，DSH 保存会话绑定并引导复用；确定性筛选提供候选，Agent 判断研究关联 | 已登记/未登记、获授权/未获授权、同名不同 Study、同一 Study 跨会话、相似但不同研究 |

求值次数指上游水文模型实际执行次数，与 LLM 请求次数分开。SCE-UA 的 rep 由解析后的有效求值上限生成，不作为第二个可冲突的裸字段；ngs、kstop、peps、pcento、random_seed 等继续按公开 Decision Space 校验。其他已验证优化器保留各自原生停止条件，如 GA 代数或 SciPy 迭代条件；无通用求值额度不等于取消这些科学参数。

快速和精细方案的数值在实现时以已验证模型、维数、固定数据和种子的基准实验确定，不直接沿用 64 次作为通用快速值。方案、版本、参数覆盖、有效上限、有效时限、随机种子、数据划分及实际停止原因全部写入结果；独立 validation 继续使用既有参数引用和账户规则。默认不限额与有限配置下的全局验证容量分别回归。

### 4.3 五个有序工作包

1. **兼容、覆盖与安装原型。** 核实指定桌面 EXE、版本、Host 与插件入口，记录依赖锁指纹和 30 项覆盖矩阵。在隔离目录构建同仓 DSH bundle，经受支持的管理入口装入目标桌面端，用普通 Agent 验证一个只读操作、同源 skill 和一个 jobs 长操作后确定单一接入路径。名称、说明和图标随发行提供，不手改 profile 绕过管理器。
2. **私有环境与节点准备。** 复用现有安装器，插件自动准备固定 uv/Python、锁定五包、配置与演示数据；仅复用插件可管理且基线一致的环境，不静默绑定任意现有节点、开发 .venv 或同级源码。展示位置、空间、进度和可恢复失败。已有存储需显式选择且保留备份；安装结束报告就绪，不初始化研究或开算，不以 npm 隐式安装脚本完成全部部署。
3. **确定性执行与率定方案。** 先完成 4.2 的共享层改动、上游支持核实和方案基准实验，更新公共 schema、Policy、Resolved Task、停止原因、状态与用量，再同步 MCP、CLI 和 skill。测试使用显式有界参数；生产默认不因测试便利恢复隐藏额度或超时。
4. **四模块、后台任务与 Study。** 接入全部现有公开能力与指导；关联 DSH job、execution_id、task_ref、Study 和产物。实现会话首次绑定、已授权研究发现及历史提醒；按数据、率定验证、训练评估、绘图指标贯通普通 Agent。工作占用时返回容量，不自动排队；提交后会话可继续交互，完成通知带结果引用。
5. **发行工件与桌面验收。** 在非源码目录用真实打包工件完成 4.5 全部门槛，覆盖重启、重复安装、取消、禁用/卸载和异常恢复。插件停用或升级按安全生命周期处理，保留数据、Study 和权重；活跃任务存在时阻止不安全切换，不强杀。记录兼容范围和是否需重启；官方目录收录单列发布事项，不把可安装等同于已上架。

### 4.4 失败与执行语义

| 情况 | 插件和 Agent 的行为 | 验收观察 |
|---|---|---|
| 缺环境、缺授权、缺数据、preflight.ready=false | 报告具体缺项；不把工具已注册当作可运行，不静默下载或扩大权限 | 无科学任务误提交，无科学额度增加 |
| RESOURCE_BUSY 或显式有限额度不足 | 返回当前容量、占用和查询方式；有限部署在原 Study 申请授权 | 不自动排队，不创建新根目录、新 Study 或另一通道绕过限制；默认不限累计额度不因旧有限值拒绝 |
| 提交后断线、桌面重开 | 先按保存的 execution_id/task_ref 查询原结果 | 没有重复率定、训练或重复扣账 |
| 超时、取消或科学失败 | 保留原错误码、任务引用、已结算用量和合法产物；只提供已实现的取消能力 | 不把取消等待当成计算已终止，不自动重跑整个科学操作 |
| 关闭插件或更新版本 | 释放插件自有注册和进程资源，保留公共环境与研究；活动任务存在时阻止不安全切换 | 其他会话和研究记录完整，失败原因可见 |

跨进程错误保留 code、retryable、details 及实际用量，不解析自然语言猜错误类别。DSH transport 重连不等于重新提交科学任务。DSH jobs 是必需接入，用于后台生命周期、通知、取消和日志；科学准入、幂等、计数、结果与中断结算仍由 hydrosystem 持有。job_id、execution_id 和 task_ref 分别保留，不互相冒充。

DSH 仍在运行时，任务应在后台继续；最小化、关闭窗口但进程仍在以及完全退出分别实测。首版不承诺应用完全退出后继续、独立守护或优化器续算。完全退出再打开时，先核查既有执行所有者和产物，只有确认无存活所有者才按既有 reconciliation 结算中断；不释放仍存活进程占用，也不自动重跑原 Task。

## 5. 第二阶段：组装水文 preset

前提：第一阶段已在真实桌面端通过。优先随同一 hydrosystem bundle 提供可选 preset；它不覆盖 standard，不自动改变用户默认智能体，不要求另建仓库。

1. **组合。** 使用 DSH 普通 preset 声明组装现有模型路由、工具、技能和必要上下文；先提供一个水文研究 preset，不预先拆成四个 Agent 或引入多 Agent 协作。服务放 Host，作用域贡献放 preset；需要隔离时提供者和消费者位于同一 realm。
2. **研究指导。** 常驻提示只保留职责、当前节点/Study、权限边界和 skill 路由；按任务读取数据、率定、训练、分析 skill。具体参数范围与默认值来自当前 describe/preflight/schema，不维护第二份手工水文参数表。
3. **研究流程。** 理解目标，发现可用能力，查询并提示已授权的历史研究，复用或显式初始化 Study，预检，提交具名操作，读取真实结果，再决定下一次 Task。未指定率定方案时沿用第一阶段的快速默认及报告选项；有限部署额度不足时请求原 Study 续额。自动推理可以探索，系统约束不由提示词修改。
4. **会话关联。** 新会话明确选择既有研究或新研究；切换聊天不隐式换 Study，一个 Study 可以被多个获准会话访问但仍共用资源与科学账户。上下文压缩和 Session 恢复不丢失绑定；插件版本更新不静默改变活跃会话的组合。
5. **验收。** 在新会话选择 preset，完成四类代表任务；再验证恢复已有研究、跨模块引用、缺数/拒绝/耗尽处理，以及“说明限制而不编造结果”。模型与工具输出按仓库测试政策保存 keyless 记录；真实桌面场景证明 Agent 确实加载了指导并调用正确工具。

阶段交付：可选择的水文智能体、同源指导、代表对话与执行记录。preset 不拥有科学预算、任务真相或上游算法，也不负责弥补插件安装失败。

## 6. 第三阶段：基于 DSH 的水文研究工作台

前提：工具与 preset 已可独立使用。先做 DSH Client 扩展，不先 fork 一个新桌面壳；复用已有页面、右侧栏、工具卡、主题和多语言机制。独立品牌安装包在这一阶段结束后评估，当前不作为用户已确认的交付要求。

### 6.1 借鉴 OpenResearch 的内部设计

| OpenResearch 的机制 | 水文侧对应设计 | 本期不照搬的部分 |
|---|---|---|
| 实验树及父子关系 | Study 下展示已有 Trial 和验证证据；数据/绘图任务有任务记录，不伪装成 Trial | 不强制每次率定或每个候选参数创建 Git 分支 |
| 运行绑定确切代码快照与结果证据 | 展示不可变 Resolved Task、输入数据身份、环境基线、产物哈希和真实指标 | 不从日志文本猜测科学参数，也不重建另一套账本 |
| 独立 supervisor、状态跟踪与完成通知 | 先复用 hydrosystem 状态与 DSH 任务机制，显示查询时间、失联/未知状态和安全下一步 | 不直接承诺关闭应用后继续运行、远程恢复或优化器断点续算 |
| 常驻 playbook 与模块化 skill | 当前研究摘要常驻，操作细节按需加载；工具和指导同版本发布 | 不把所有上游文档塞进每轮提示词 |
| 日志、图表和报告与实验关联 | 结果、图、参数、权重和失败记录可从 Task/Trial 互相定位 | 不将“任务成功”解释为拟合良好或科学结论成立 |

### 6.2 最小界面范围

| 页面/区域 | 必须回答的问题 | 最小交互 |
|---|---|---|
| 研究概览 | 当前是什么研究、用了什么数据、额度和环境怎样 | 打开或绑定已有 Study，查看四模块就绪状态 |
| 任务与试验列表 | 在做什么、做过什么、是否已独立验证 | 状态筛选、进入详情、按现有关系比较 |
| 执行详情 | 本次有效参数、数据时期、用量、错误和证据是什么 | 查看结果、诊断、参数集或权重引用；仅在后端支持时提供取消 |
| 结果分析 | 哪个结果更符合当前目标，依据与条件是什么 | 过程线、指标比较、参数差异；标明单位、方向、数据划分和缺失值 |
| 产物与报告 | 图、数据、参数和权重在哪里，来自哪次执行 | 预览、导出或定位获准产物，并保留对应任务引用 |

比较实验前先核对模型、流域、数据时期/划分、指标定义和单位；不兼容结果标明差异，不生成误导排名。结果页来自结构化结果，不能以重新运行计算来刷新视图。产物路径与哈希经现有接口验证，远端路径不可直接当作本机可打开文件。

### 6.3 状态、恢复与交互实现

1. hydrosystem 继续持有科学事实；DSH Session 保存绑定、操作引用和模型实际看过的结果。UI 当前状态通过查询刷新，记录查询时间，离线时明确展示最后已知状态。
2. 可由 Session 日志恢复的绑定/显示状态使用 DSH Session Projection；恢复纯计算，不发工具调用、不访问科学文件、不触发训练或率定。进程句柄、监听器、进行中的请求留在运行时，并通过 Cordis effect 释放。
3. 按需使用现有日志、RPC 和投影视图。只有现有公开查询无法满足页面时，才增加调用方无关的 hydrosystem 查询接口；结果页不直接读取内部 ledger 布局，不给浏览器任意文件访问权。
4. UI 操作和 Agent 工具进入同一应用服务与授权路径。运行中阻止重复提交；字段校验在表单显示，查询失败保留已加载数据，长期未知/失败状态保持可见；消息通过 typed locale 字典输出。
5. 验证浅色/深色、键盘、缩放、错误和长任务状态；首版桌面为主要验收，若对 Web 声明支持，还需通过 390 CSS px 的主要操作可达性检查。使用真实服务器、真实工具和模型流程录制 GIF；公开 PR 含 GUI 行为变更时附带对应证据，不能用静态效果图代替。

## 7. 实施顺序与检查方法

### 7.1 第一阶段开工顺序

1. 固定已下载桌面端身份和插件兼容范围，保留现有 hydrosystem 本地改动，确认可复用的安装/更新实现，建立 30 项能力及 A—E 验收矩阵。
2. 在隔离环境完成只读能力、skill 与 jobs 长任务的真实桌面安装原型，验证启动、关闭和重开，再确定正式接入方式；同时核实上游无求值上限支持。
3. 完成私有环境准备及公共层的可选限额/时限、版本化率定方案与有效参数记录；完成方案基准及相关公开行为回归。
4. 完成普通 Agent 全量接入、后台生命周期、Session–Study 关联和授权历史发现；四类闭环复用同一基线和演示 Study，另设不同 Study 验证发现与隔离。
5. 完成无源码依赖的发行包安装、全部 A—E 门槛、三入口语义回归与恢复，出具可复查验收报告后进入 preset 阶段。

### 7.2 分层验证

| 层次 | 检查内容 | 执行原则 |
|---|---|---|
| hydrosystem 公共行为 | 正常、边界和失败请求；授权、预算、幂等、用量、产物与中断结算 | 从需求和已验证参考推导预期；优先真实内部模块，外部网络/服务才按需 mock |
| 接入与发行工件 | schema/skill/错误一致性；路径含空格；缺环境；重复安装；卸载与重连 | 使用真实发行包与隔离目录；不把源码 editable 通过当成发布通过 |
| 科学闭环 | 固定演示配置，快速/精细与自定义、率定后验证、训练后权重评估、指标与图 | 测试显式设置有界条件，精细不限次用短小真实收敛案例；检查真实输入、用量和产物，不将测试限制写回生产默认 |
| DSH Agent 与恢复 | 第一阶段普通 Agent、后台 jobs、Study 绑定与历史、上下文恢复、断线后先查状态；第二阶段另测 preset | keyless 记录验证确定输出；另做真实模型实测，分别报告，未配置时不能声称通过 |
| UI 与平台 | 页面、交互、恢复、主题、可访问性和目标桌面版本 | 部件测试加真实桌面验收；新增跨平台支持须分别实测，不泛化单平台结果 |

现有 Python 检查入口可按改动选择：`uv run --no-sync pytest tests/test_capabilities.py tests/test_cli.py tests/test_mcp_protocol.py tests/test_package_mcps.py`；涉及研究、运行和安装时增加对应的 `test_study_*`、`test_runtime.py`、`test_local_installation.py` 和环境测试。DSH bundle 的 TS 检查和打包脚本随原型建立，不把尚未存在的命令写成已可执行命令。

需要修改 DSH 源码时，先用 dsh-pre-push-checks 选择最小相关检查，按目标版本脚本执行 typecheck、lint、build、快照和文档检查；不默认运行全仓测试。接口破坏时同步消费者和升级指导，Session/SDK 变化按仓库规则处理。所有阶段记录命令、退出码、精确版本、产物路径和未验证项，不把历史通过作为当前证据。
